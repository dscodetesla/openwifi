# R2 build, RAM test and persistent deployment

## Freeze and build

Use a fresh checkout for this R2 profile: the common Buildroot output is shared with other board profiles. Do not run concurrent builds into the same output directory.

```sh
git clone --branch chore/plutosky-r2-rnd-checkpoint-2026-10-26 https://github.com/dscodetesla/openwifi.git
git clone https://github.com/open-sdr/openwifi-hw-img.git
git -C openwifi-hw-img checkout 64f27c5f897a807cf58fc383dd4b08c728abc07c
cd openwifi
git submodule update --init buildroot
sha256sum ../openwifi-hw-img/boards/plutosky_r2/sdk/system_top.xsa
OPENWIFI_XSA=../openwifi-hw-img/boards/plutosky_r2/sdk/system_top.xsa \
MAKEFLAGS=BR2_JLEVEL=8 ./buildroot-build.sh plutosky_r2 build
```

Expected XSA SHA256: `e684d2908da3d159d1c7a797a3994aadd80449f4d907cd7334b989ce8c988c1e`. The XSA targets XC7Z020 CLG484 -2 and was generated by Vivado2022.2; consuming the supplied XSA does not require running Vivado. The actual host had GCC15; C17 is scoped to host DTC, preserving Werror. The Linux tarball is the exact original ADI commit, not a new kernel revision.

Generated BOOT.BIN/SPL and U-Boot are build outputs; they were NOT installed. The verified R2 path retains the factory FSBL/U-Boot and replaces qspi-linux only.

For an incremental source change, rebuild the Openwifi package before rootfs packing. Rootfs rebuild/board assembly alone does not automatically prove that modified local driver source was resynchronized. The session used Buildroot `openwifi-rebuild`, then the normal common-system make and `assemble-board.sh`; inspect their exit status and the module embedded in the actual CPIO/FIT.

## Check the actual image

The packager emits a DFU-suffixed FIT. Run an independent `dfu-suffix -c` check. After successful suffix validation, a plain FIT is the DFU file without its final16 bytes; confirm FDT magic and header totalsize. Keep both artifacts and SHA256 digests.

Check that the FIT contains the expected DTB, bitstream, kernel and exact rootfs archive; the CPIO must contain the intended sdr.ko and executable S42/S43/S95. Do not infer the Flash result from a neighboring host file.

## RAM-first gate

Use DEBUG FTDI UART interface01 at115200, not interface00/JTAG. The actual vendor U-Boot supported:

```text
loady 0x2080000 921600
```

Wait for the receiver prompt, change host UART speed and send with lrzsz `sb -b -k --ymodem`. After completion, return to115200 and repeat ESC until the U-Boot prompt; a single early ESC was lost. Validate actual filesize and CRC32, run iminfo, then direct bootm with the selected FIT configuration. The initial RAM test avoided saveenv and adi_loadvals.

Verify Linux/IIO, Ethernet, channel/width, auto-ACK register and real RX capture. Native USB was not a reliable transfer path.

For topology-compatible driver changes, use RAM module replacement and `OPENWIFI_RELOAD_FPGA=0 ./wgd.sh 0`; always reapply monitor/channel/AGC and XPU11=16 after interface initialization. A successful insmod does not qualify RF TX.

## Persistent write gate

Before any new write, independently verify the target's JEDEC and MTD layout, complete32MiB recovery backup, stable power, correct plain FIT, hashes, qspi-linux offset0x200000 and size0x1e00000. Factory MTD exposed only14MiB of Linux and lower16MiB overall. Never use those old14MiB DFU mappings for the larger21MiB FIT.

The audited writer CLI order is **image first, MTD device second**:

```text
mtd_flash_write verified-firmware.itb /dev/mtd3
```

The session initially reversed these arguments; the writer rejected an empty-image interpretation before erase. Usage was checked and the order corrected. A missing image/failed guard is not a successful write.

Stop RX before programming. The actual4096-byte erase geometry took roughly5–6minutes for30MiB; preserve live PID/start identity and phase checkpoints, and do not launch another writer merely because the log is quiet. Require full writer readback, independent payload digest, unchanged bootchain/NVMFS digests and a normal Flash reboot.

The recorded final FIT is21235108bytes. Saved fit_size=0x14405a8 reads21235112bytes, including4 erased bytes after FIT. No environment rewrite was needed for this slightly smaller payload. The preceding U-Boot environment save completed with literal `done`, not `OK`; its CRC and readback were verified independently. Do not repeat saveenv solely because a script expected the wrong success text.

## Runtime acceptance and offline checks

Record board uptime and host UTC before changing a board clock that starts at1970. Preserve original logs. Do not publish identifiers or private capture contents.

```sh
iw dev sdr0 info
/root/openwifi/sdrctl dev sdr0 get reg xpu 11
cat /var/log/openwifi-monitor.log
tcpdump -i sdr0 -Q in -s0 -U -c 300 -w /tmp/rx.pcap
```

The minimal target lacks timeout; bound captures from the host and send SIGINT on timeout. This is unrelated to packet quality.

Offline, on the capture host:

```sh
python3 tools/analyze_openwifi_r2_pcap.py capture.pcap --expect-consistent
```

This tool checks classic PCAP/radiotap and the recorded R2 FPGA trailer convention. It prints counters and a digest, not identities/payloads. It is not a generic pristine-FCS validator. The historical pre-fix capture must exit1 for two metadata inconsistencies; fixed RAM/Flash captures exit0. Private PCAP files are deliberately absent from Git.

No AP, packet injection, automated reboot workaround or long-term monitoring daemon was introduced.
